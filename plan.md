# Convert: architecture and implementation plan

A Blazor WebAssembly app that converts, edits and renders files entirely in the browser. The user drops a file, sees a preview, picks a target format, picks a tool when several can do it, fills that tool's options, previews the result and downloads it. New file types and tools are added as "packs" whose heavy assemblies lazy-load.

Status: nothing is built yet. This document is the plan plus every piece of context needed to implement it without re-researching.

```csharp
public enum FileKind { Binary, Text }
public enum FileGroup { Documents, Images, Data, Text }

public sealed record FileType(
    string Id, string DisplayName, IReadOnlyList<string> Extensions, string ContentType,
    FileKind Kind, Icon Icon, FileGroup Group, string PageNoun = "page");

// Core-owned so two packs emitting the same format agree on identity.
public static class FileTypes
{
    Docx, Xlsx, Pptx, Pub, Pdf, Html, Markdown, Text, Mermaid, Svg, Png, Jpeg, WebP,

}

public sealed record Tool(string Id, string DisplayName, string Description, string ProjectUrl, string License);

// One record for input, each output part, and the preview/editor parameter.
public sealed record Document(string FileName, byte[] Bytes, FileType Type);
public sealed record ConversionOutput(IReadOnlyList<Document> Parts, IReadOnlyList<string> Notes); // >1 part => UI zips
public sealed record ConversionProgress(string Label, string? Detail);

public abstract class Conversion
{
    public abstract string Id { get; }                         // "docx-pdf-morph"
    public abstract FileType Source { get; }
    public abstract FileType Target { get; }
    public abstract Tool Tool { get; }
    public abstract string Summary { get; }                    // one line on the tool picker
    public virtual string? Expect => null;                     // what carries over / what doesn't (OfficeIMO's `expect`)
    public abstract IReadOnlyList<string> Assemblies { get; }  // transitive closure of lazy .wasm names
    public virtual Type? OptionsComponent => null;             // an OptionsPanel<TOptions> in the pack assembly
    public virtual int Priority => 0;                          // lower first when several tools serve one pair
    public abstract object CreateOptions();
    public abstract Task<ConversionOutput> RunAsync(Document source, object options, IProgress<ConversionProgress> progress, Cancel cancel);
}

public abstract class Conversion<TOptions> : Conversion where TOptions : class, new()
{
    public override object CreateOptions() => new TOptions();
    public override Task<ConversionOutput> RunAsync(Document source, object options, IProgress<ConversionProgress> progress, Cancel cancel) =>
        RunAsync(source, (TOptions) options, progress, cancel);
    protected abstract Task<ConversionOutput> RunAsync(Document source, TOptions options, IProgress<ConversionProgress> progress, Cancel cancel);
}

public sealed record Preview(FileType Type, IReadOnlyList<string> Assemblies, Type Component, int Priority = 0);
public sealed record Editor(FileType Type, IReadOnlyList<string> Assemblies, Type Component);
// Preview components: [Parameter] Document Document.  Editor components add [Parameter] EventCallback<Document> Changed.

public abstract class OptionsPanel<TOptions> : ComponentBase
{
    [Parameter] public TOptions Options { get; set; } = default!;
    [Parameter] public EventCallback Changed { get; set; }
}

public delegate FileType? Sniffer(string extension, ReadOnlySpan<byte> bytes);   // BCL only; disambiguates .json/.csv/.txt

public interface IPack
{
    void Register(ConversionRegistry registry);
    void Loaded(IServiceProvider services) { }   // called once after the first successful load of any of this pack's entries
}

public sealed class ConversionRegistry
{
    // Add(FileType | Conversion | Preview | Editor | Sniffer | Sample); duplicate ids throw.
    // Registering a FileKind.Text type auto-registers Core's TextEditor for it.
    public FileType? Detect(string fileName, ReadOnlySpan<byte> bytes);     // extension first, then sniffers
    public IReadOnlyList<TargetGroup> TargetsFor(FileType source);          // grouped by Target and FileGroup, conversions ordered by Priority
    public IReadOnlyList<Preview> PreviewsFor(FileType type);
    public IReadOnlyList<Editor> EditorsFor(FileType type);
    public IReadOnlyList<Sample> Samples { get; }                            // (DisplayName, Icon, AssetUrl, FileName)
    public string Accept { get; }                                            // every readable extension, for <InputFile accept>
}
```

## 4. Lazy loading: the part that must be right

### 4.1 How Mono resolves references

Mono resolves metadata per **method at first interpretation** and per **class at first layout**. Anything touched at startup (packs, descriptors, options POCOs, sniffers, `Program.cs`, `App`, layout, wizard page) must obey:

| Construct | Loads the heavy assembly? | Rule |
|---|---|---|
| Field / auto-property of a heavy type (including a library **enum**) | Yes, at class layout | Options POCOs and descriptors use Core/BCL types only; mirror library enums in the pack. |
| Base type / interface from a heavy assembly | Yes | Compose, never derive (`class MorphPreview : MorphViewer` is forbidden). |
| Generic argument `Conversion<MorphOptions>` | Only if the argument is heavy | Pack POCOs are fine. |
| `typeof(X)` / `OpenComponent<X>` in a method body | When that method is first interpreted | Fine for pack components (eager assembly); never for library components. `Type Component => typeof(MorphPreview)` is safe. |
| Razor-generated `BuildRenderTree` referencing `<MorphViewer>` | On first render | Safe as long as the component renders after `EnsureAsync`. |
| `@inject HeavyType` in a pack component | At instantiation, and DI must resolve it | Pack components inject Core/framework services only. Morph's own components inject `MorphInterop`: see §4.3. |
| Static field initializers / static constructors | On first touch of any static member | `*Pack` and `*Conversion` classes hold no static state. Heavy statics (fonts, caches) live in `*Runner` classes. |
| `services.AddScoped<HeavyService>()` in `Program.cs` | Yes, at startup | Forbidden. |
| `Router.AdditionalAssemblies` | Reflects every type's base type | Never pass pack assemblies. Routes live only in `Convert.Web`. |
| Async state machine hoisting a heavy local across an `await` | At call time | Safe; the call happens after load. |

Pack rule: `using <heavy namespace>` only under `Runners/`, `Previews/` and `Editors/`. `RunAsync` delegates to a `static class XRunner`.

### 4.2 Transitive closure

`LazyAssemblyLoader.LoadAssembliesAsync` loads exactly the names given. A lazy assembly whose dependency is **not** in the csproj `BlazorWebAssemblyLazyLoad` list makes that dependency eager (it lands in the startup manifest). Every `Assemblies` list is therefore the closure, and the csproj list is the union of all of them.

### 4.3 Late-binding DI (`PackServices` + `PackServiceProviderFactory`)

Morph's `DocumentPreview`, `MorphViewer` and `MorphConverter` all `@inject MorphInterop` (`D:\Code\Papyrine\Morph\src\Morph.Blazor\Components\MorphViewer.razor:2`). Calling `builder.Services.AddMorph()` in `Program.cs` puts a typeref to `Morph.Blazor` into a method interpreted at startup, which loads `Morph.Blazor.wasm` eagerly. MS.DI cannot take registrations after `Build()`. Core therefore owns the provider:

```csharp
public static class PackServices
{
    static readonly Dictionary<Type, Func<IServiceProvider, object>> factories = new();
    static readonly Dictionary<Type, object> instances = new();          // WASM has one scope: scoped == singleton
    public static void Add<TService>(Func<IServiceProvider, TService> factory) where TService : class => factories[typeof(TService)] = factory;
    public static object? Resolve(Type type, IServiceProvider inner) { /* cached instance, else factory(inner), else null */ }
}

// ~70 lines. Wraps the built ServiceProvider and every scope it creates.
public sealed class PackServiceProviderFactory : IServiceProviderFactory<IServiceCollection>
{
    public IServiceCollection CreateBuilder(IServiceCollection services) => services;
    public IServiceProvider CreateServiceProvider(IServiceCollection services) => new Wrapper(services.BuildServiceProvider());

    sealed class Wrapper(IServiceProvider inner) : IServiceProvider, IServiceScopeFactory, IKeyedServiceProvider, IServiceProviderIsService, IAsyncDisposable
    {
        public object? GetService(Type type)
        {
            if (type == typeof(IServiceScopeFactory)) return this;      // WebAssemblyHost creates one AsyncScope and hands its provider to the renderer
            return inner.GetService(type) ?? PackServices.Resolve(type, this);
        }
        public IServiceScope CreateScope() => new Scope(inner.GetRequiredService<IServiceScopeFactory>().CreateScope());  // Scope wraps the inner scope's provider the same way
        // IKeyedServiceProvider / IServiceProviderIsService pass through to inner
    }
}
```

`Program.cs`: `builder.ConfigureContainer(new PackServiceProviderFactory());`

`MorphPack.Loaded(services)` calls `MorphServices.Register()` whose body is `PackServices.Add(_ => new MorphInterop(_.GetRequiredService<IJSRuntime>()));`. Constraint: `Loaded` may only touch assemblies every entry of that pack loads (true for Morph: every entry loads `Morph.Blazor`). Other packs: no-op.

### 4.4 Trimming, native, assets

- `PublishTrimmed=true`, default partial mode (not GeoConvert.Web's `TrimMode=full`). Morph.Blazor's NuGet ships `buildTransitive/Morph.Blazor.targets`, which roots `DocumentFormat.OpenXml`, `DocumentFormat.OpenXml.Framework`, `AngleSharp`, `SixLabors.ImageSharp`, `SixLabors.ImageSharp.Drawing`, `SixLabors.Fonts`, `SixLabors.PolygonClipper` (also covers OfficeIMO, OpenXmlHtml, Naiad.ImageSharp). The app adds `TrimmerRootAssembly` for `OpenXmlHtml`, `OpenXmlKit` (not verified trim-safe) and every `Convert.*` pack (tiny; removes `DynamicComponent` trim warnings under `TreatWarningsAsErrors`). `TrimmerRootAssembly` is an ILLink input and `BlazorWebAssemblyLazyLoad` is a manifest input: an assembly can be both (OfficeIMO does this with `OfficeIMO.Web.Fonts.Fallback`).
- `WasmBuildNative=true` from phase 2 so the toolchain is proven before Morph arrives. Krilla's `runtimes/browser-wasm/native/krilla_capi.a` (10.9 MB) is linked into `dotnet.native.wasm` whether or not `Krilla.wasm` (150 KB managed, lazy) ever loads: Morph's interpreted publish measures `dotnet.native.wasm` at 5.9 MB raw / 1.6 MB brotli versus ~2.5–3 MB raw for a plain runtime, so ~0.7 MB brotli fixed cost on every first visit. Comment it in the csproj. OfficeIMO NuGet packages carry no native assets (HarfBuzz is a repo project, not a package dependency), so OfficeIMO adds nothing native. HarfBuzz is not used.
- Static web assets of a lazy RCL work unchanged: `_content/Morph.Blazor/...` is produced at build/publish from the PackageReference. `MorphInterop` imports `./_content/Morph.Blazor/morph.js` lazily. `index.html` links `_content/Morph.Blazor/morph.css` and `_content/Convert.Core/convert.css` eagerly and preloads the four Aptos TTFs (`as="fetch" crossorigin`, as Morph's index.html explains).

## 5. UI flow

States **Empty → Loaded → Converting → Converted**, plus an **Edit** tab. Mirrors officeimo.com/browser tools (stepper "Add a file → Choose options → Download the result", preview on the right, options on the left, "More options" expander) and Morph's converter.

1. **Empty:** one panel. Full-page drop (Morph's `acceptFileDrops` in `morph.js` routes a drop anywhere into the `<InputFile>` so one `OnChange` path handles both), "Choose a file", "Paste text" (creates a text `Document`; asks which text type when ambiguous), sample buttons contributed by packs (fetched on demand from `_content/<pack>/samples/`).
2. **Loaded:** `ConvertSession.LoadAsync` → `registry.Detect` (extension only is reliable; browser MIME types are empty for Office files) → left pane `PreviewHost`: `ToolLoader.EnsureAsync(preview.Assemblies)` with a progress bar, then `<DynamicComponent Type=preview.Component Parameters={Document}>`. Right rail: **Convert to** chips grouped by `FileGroup`; picking a target shows the **tool picker** when >1 conversion serves the pair (radio list with `Summary`, ordered by `Priority`, first selected), then `OptionsHost` (`DynamicComponent` of `OptionsComponent` with `{Options, Changed}`), the `Expect` note and the Convert button. **Edit** tab (when an `Editor` exists) swaps the preview for the editor; `Changed` → `ReplaceSourceAsync` (invalidates the result cache, re-renders the preview).
3. **Converting:** `EnsureAsync(conversion.Assemblies)` then `await Task.Run(() => conversion.RunAsync(...), cancel)`. Runners yield between pages (`await Task.Run` per page + `StateHasChanged`, as `MorphConverter.RenderPreviewAsync` does) so the browser paints. A `CancelSource work` is reset whenever the source changes (Morph's `ResetAsync` pattern).
4. **Converted:** result pane reuses `PreviewHost` for `Parts[0].Type` (`PartsPreview` lays out one child preview per part), lists `Notes`, offers **Download** (one part → file; several → `ZipParts`, naming `page_0001.png`… like Morph's `ZipPages`) and "Start over". Results cached per conversion id for the life of the source.

Errors: `ErrorPanel` + `IssueLauncher` (copy from Morph.Blazor `Services/IssueLauncher.cs`) pointing at `https://github.com/SimonCropp/Convert/issues/new`.

Core components: `DropZone`, `PreviewHost`, `TargetPicker`, `ToolPicker`, `OptionsHost`, `ChoiceOption`, `FlagOption`, `NumberOption`, `TextOption`, `AdvancedOptions` (collapsible), `ProgressBar`, `ErrorPanel`, `Previews/TextPreview` (`<pre>`), `Previews/ImagePreview` (`<img src=blob>`), `Previews/SvgPreview` (inline markup), `Previews/FramePreview` (sandboxed `<iframe sandbox="">` for html; blob URL), `Previews/PartsPreview`, `Editors/TextEditor` (textarea, ~300 ms debounce like Naiad.Web's 250 ms, fires `Changed` on idle). Option panels are hand-written Razor composed from these controls with `@bind-Value`; no JSON option schema.

`BrowserInterop(IJSRuntime)` modelled on `MorphInterop`: lazy `import` of `_content/Convert.Core/convert.js` cached in a `Task<IJSObjectReference>`; `DownloadAsync(fileName, contentType, bytes)`, `CreateObjectUrlAsync`, `RevokeObjectUrlAsync`, `AcceptDropsAsync(ElementReference input)`, `UserAgentAsync`. `byte[]` crosses to JS as `Uint8Array`, no base64.

## 13. Code conventions

- Long "why" comments in csproj files are the norm (see Morph.Web.csproj).
- Never write files with heredocs; never add a `Co-Authored-By: Claude` trailer.
